# Neil Mitchell Portfolio v2.2.1

Version 2.2.1 is a focused production hotfix for two mobile regressions reported after the Works
release and a related timeline-alignment defect found during review.

## Visitor-facing fixes

- Keeps the Approach section's vertical delivery rail in a dedicated mobile column so the divider
  no longer crosses stage headings or descriptions.
- Resets retained scroll positions when entering `/works` or `/works/deep-live-cam`, ensuring the
  Works index and case study open at their page titles on affected mobile browsers.
- Aligns the fifth `Responsible use` timeline step with the same mobile rail and content column as
  steps 1–4.
- Preserves the existing desktop and tablet layouts, home-page anchor scrolling, project content,
  attribution, and licensing boundaries.

## Maintainer changes

- Adds a route-aware client reset to the shared Works layout. It temporarily disables smooth
  scrolling, resets the page before paint, and restores the visitor's prior scroll-behaviour style.
- Reflows the phone-width delivery map into a rail-and-content grid consistent with the case-study
  timeline.
- Adds source validation for the mobile regression contracts.
- Records and links the production defects in GitHub issues
  [#9](https://github.com/CRSD-Lau/Personal-Site/issues/9) and
  [#10](https://github.com/CRSD-Lau/Personal-Site/issues/10), plus the during-review alignment defect
  in [#11](https://github.com/CRSD-Lau/Personal-Site/issues/11).

## Verification

- Formatting, ESLint, TypeScript, content validation, and the static production build pass.
- `npm audit --audit-level=high` reports zero known vulnerabilities.
- Browser checks at 320, 360, 390, and 430 CSS px confirm the delivery rail does not overlap copy
  and both Works entry paths reach the case study at scroll position 0. All five case-study timeline
  nodes and headings align at those widths.
- Desktop verification confirms the six-column delivery map remains centred and unchanged.
- GitHub Actions, CodeQL, Vercel Preview, and the exact production deployment are required to pass
  before the release tag is published.

## Rollback

Version `v2.2.0` and commit `8d582a9` remain the immediate rollback point.
